About Kan-Linux

Project Kan-Linux aims to deliver a minimalist, secure and modern pure Wayland Desktop-OS, letting users choose what to install from official prebuilt binary, source code or by Kan-Agent . It comes with a featured set of development toolchains (GCC, LLVM, Java, Perl, Python, Go, Rust, Node.js), Firefox, Wireshark, VLC, GIMP, featured terminal, featured File Manager, featured Coding Agent, featured snip tool, various CLI tools and a lean desktop shell(currently a highly-customized Omarchy desktop shell ), it is a bare-bones OS with no bundled office suite. The reasoning is that every user has their own preferences for what to install on their computer, while following the "Convention over Configuration" philosophy.


For developers, Kan-Linux can serve as a concise and secure Desktop-OS on real hardware.

For AI researchers, Kan-Linux can serve as a good testbed on real hardware.


In short, the main goal of Kan-Linux is to build a concise, secure and Agent-first Linux distro at the edge --- locally and in the cloud. No telemetry, no phoning home, no ads, 100% free for personal, institutional and commercial use.

Philosophy

Kan-Linux (or KanLinux) is a concise, secure and Agent-first Linux distribution. The name Kan (勘) derives from Wang Yangming 's Instructions for Practical Living, representing the philosophy of breaking through technical obscurations and returning to the system's original simplicity.

Design principles

Simplicity

Eliminate overly complex wrapper layers and over-engineering, following the core philosophy of ggml/llama.cpp. Kan-Linux is not dependent on any existing Linux distribution.

  • Keep the LiveISO compact(ubuntu-26.04-desktop-amd64.iso ~6.1 GiB, pop-os_24.04_amd64_generic_27.iso ~3.3 GiB, cachyos-desktop-linux-260809.iso ~3.0 GiB, omarchy-4.0.6.iso ~6.3 GiB, omarchy-4.5.0-x86.iso ~ 6.1 GiB, deepin-desktop-community-25.2.0-amd64.iso ~6.5 GiB, kan-linux-0.3.2-x86_64.iso ~ 1.9 GiB, kan-linux-v0.3.3-x86_64.iso ~ 2.0 GiB) while supporting a rich set of modern desktop features.
  • The full self-hosting bootstrapping pipeline covers only the OS base system. Heavy desktop applications (Chromium, office suite, …) are built separately on top of a fully bootstrapped Kan-Linux instance and distributed as optional artifacts — similar to the pinned official Firefox tar.gz / tar.xz releases.
  • No GNOME or KDE desktop stacks. While GTK and Qt are capable toolkits, Kan-Linux builds a lean, minimal desktop environment from scratch. Applications are pluggable, with no mandatory global metadata, introspection subsystems, or complex hidden runtime contracts.

Monorepo

Drawing lessons from many existing Linux distributions and the highly complicated Yocto Project, Kan-Linux adopts an AOSP-style single-repository architecture. All source code resides in one repository to simplify development, builds and maintenance.

Secure

Our goal is not an unbreakable system, but to shrink the TCB and attack surface, while maximizing SBOM clarity and supply-chain security.

  • Optimized for single-user desktop workflows to reduce attack surface(inspired by ideas in AOSP).
  • Source-built — the base OS and its components are compiled from source, with a small explicit exception list: prebuilt artifacts such as Go, Rust, Firefox, Vulkan SDK and user-installed software. This maximizes SBOM transparency and supply-chain auditability.
  • SELinux is excluded intentionally to keep the TCB minimal.
  • AI-native security audit pipeline — Kan-Linux embeds LLM-powered source-level security auditing (GLM-5.3 and other high-capability models) as a mandatory pre-compilation gate, complementing human review. Security validation shifts from post-hoc binary scanning to source-code admission review.
  • Kan-Linux starts with zero external network activity by default. No silent update checks, no telemetry, no phone-home. Kan-Linux only talks when you tell it to. Verify it yourself with the bundled Wireshark. More advanced hardening is planned.
  • 100% full self-hosting; 100% reproducible builds.

Agent-First

  • Only Flatpak is provided(since v0.3.4), no other traditional package manager. AI agents are a core component of Kan-Linux: they autonomously compile, deploy, install components, run system health checks, and resolve issues.
  • llama.cpp-First — a native, integrated llama.cpp edge inference engine is provided for local AI deployment.
  • Maintain a balance between Agent-first automation and plain human-readable interfaces and workflows.

Differences and connections with Omarchy-Linux

  • Omarchy-Linux targets end users, delivering an out-of-the-box complete desktop system, with visual polish as one of its core goals. Kan-Linux is built for programmers and AI researchers, providing a neutral, modern pure Wayland-based Linux distribution. Focused on controllability, auditability (no black-box within the OS), modularity and reproducible builds — and visual polish is not a project objective.
  • Kan-Linux draws inspiration from Omarchy's desktop shell and integrates it as our optional early default desktop shell. We port this tasteful shell as an upper-layer UI example to show the capabilities of the Kan-Linux platform. Even if we remove or disable the Omarchy desktop shell in the future due to unexpected reasons, the whole system and graphics infrastructure can still run fully and independently.
  • Omarchy-Linux is based on the upstream Arch Linux distribution, while Kan-Linux is built completely from scratch and does not rely on any upstream Linux distribution.
  • Kan-Linux provides Omarchy-comparable desktop UI and keybindings plus powerful development environments for programmers and AI Agents.
  • In short, Kan-Linux is another HyperOS if Omarchy-Linux is Google Android.

Differences with Rocky-Linux

  • Rocky-Linux is an Enterprise-OS while Kan-Linux is a Desktop-OS.
