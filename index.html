What is Kan-Linux?

Kan-Linux (or KanLinux) is a Simplicity, Source-Built, Agent-First Linux distribution.

The name · 勘

Kan (勘) derives from Instructions for Practical Living by Wang Yangming — breaking through technical obscurations and returning to the system’s original simplicity. It also stands for “see through the delusions and return to simplicity.”

The goal

Enable programmers and AI researchers to build their own Linux OS (Omarchy-style, for example) from the full source code with minimal setup on a wide range of hardware — locally and in the cloud.

How it’s built

An AOSP-style monorepo holds component sources and verified patches — from toolchain and libc through system utils, mesa and the Wayland desktop stack. The OS is compiled from source, not assembled from an upstream distro, so builds stay reproducible and auditable end to end.

Who it is for

Programmers, AI researchers and Linux distribution builders who want controllability, auditability (no black-box within the OS), modularity and reproducible builds — not a polished out-of-the-box consumer desktop.

Design Principles

The Kan-Linux way: Simplicity, Open Core, Safety, Explore and have fun

  • Minimal

    We like simplicity and aim to keep the distribution as small and as simple as possible. Eliminate overly complex wrapper layers and overengineering, following the core philosophy of ggml/llama.cpp. Not dependent on any existing Linux distribution.

  • Monorepo

    Drawing lessons from existing Linux distributions and the highly sophisticated Yocto Project, the project uses an AOSP-style single-repository architecture. All source code is stored and hosted in one single code repository to simplify development, build and maintenance work.

  • Source-Built

    The entire OS and all components are built from source. Every component ships with verified custom patches, and self-contained source snapshots can produce a live ISO directly from source code.

  • llama.cpp-First

    Built-in native llama.cpp edge inference engine for local AI deployment — keep inference close to the metal, without heavy external runtimes.

  • Agent-First & AI-native security audit

    Supports AI agents to autonomously compile, deploy, install components, run system checks and resolve issues. Kan-Linux embeds LLM-based source-level security audit (GLM-5.3 and others) as a mandatory gate before compilation. Security is shifted from “binary post-scanning” to source pre-admission auditing.

  • Safety

    Kan-Linux makes no external network activity after boot — no silent update checks, no telemetry, no phone-home. Kan-Linux only talks when you tell it to. Verify it yourself with the bundled tshark (the Wireshark CLI).

  • Open development

    The development process is open and everyone is welcome to join. Explore and have fun — contributors are encouraged to try crazy ideas, build wild demos, and push the edge of what’s possible.

Differences & Connections with Omarchy

Inspired by Omarchy — but aimed at a different audience and a different layer of the stack.

Omarchy

  • Targets end users, delivering an out-of-the-box complete desktop system.
  • Visual polish as one of its core goals.
  • Based on the upstream Arch Linux distribution.

Kan-Linux

  • Targets programmers, AI researchers and Linux distribution builders.
  • Provides a neutral Wayland underlying graphics platform.
  • Core goals: controllability, auditability (no black-box within the OS), modularity and reproducible builds. Visual polish is not a project objective.
  • Built completely from scratch and does not rely on any upstream Linux distribution.

Kan-Linux draws inspiration from Omarchy("Convention over Configuration") and Omarchy’s desktop shell, and integrates it as our optional early default desktop. We port this shell as an upper-layer UI example to show the capabilities of the Kan-Linux platform. Even if we remove or disable the Omarchy shell in the future, the whole system and graphics infrastructure can still run fully and independently.

Roadmap

From QEMU PoC to bare-metal self-hosting and desktop-native AI agents.

  1. Stage 1: PoC validation Done

    Complete PoC validation of Kan-Linux via QEMU virtual machine.

  2. Stage 2.1: Omarchy shell in QEMU Done

    Integrate a preliminary, feature-limited, customized Omarchy desktop shell and login greeter for QEMU virtual machine environments.

  3. Stage 2.2: Installer DONE

    Enable and validate Kan-Linux installer via QEMU virtual machine

  4. Stage 2.3: Physical x86_64 desktop PCs / laptops IN PROGRESS

    Enable and validate Kan-Linux boot and runtime support for physical x86_64 desktop PCs / laptops.

  5. Milestone: Bare-metal install & full self-hosting Planned

    Kan-Linux LiveISO supports bare-metal installation. Kan-Linux achieves full self-hosting — all subsequent development, building and iteration of Kan-Linux will happen inside Kan-Linux itself.

  6. Stage 2.4–2.5: Desktop-native AI Agent Planned

    Integrate desktop-native AI Agent in Kan-Linux on physical x86_64 hardware, then fully verify desktop-native AI Agent functionality on desktop and laptop hardware.

  7. Stage 2.6: Stabilize the Omarchy shell Planned

    Refine and stabilize the Omarchy desktop shell for physical x86_64 desktops and laptops.

  8. Stage 3: Refine Planned

    Refine and stabilized Kan-Linux on physical x86_64 hardware.
